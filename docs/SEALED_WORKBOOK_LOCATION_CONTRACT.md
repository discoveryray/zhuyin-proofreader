# Selected-project sealed workbook locations

`sealed-workbook-location/1` supports moving or renaming the project root. Internal workbook names and the two producer role directories remain unchanged; workbook/PDF rename migration is outside this contract.

The selected project root owns every workbook read/write. A sealed manifest associates each unique PDF SHA and actual/candidate role with an exact workbook SHA and a trusted two-part relative locator. The finite legacy absolute-role adapter extracts only the final known role/name descriptor; it never opens the historical absolute origin, substitutes a drive, or searches outside the selected root. Relative traversal, unknown roles, links/junctions, hardlinks, missing/wrong SHA and duplicate matching files fail closed. Filename alone is insufficient; all role-local SHA candidates are considered and ambiguity is rejected, including a second same-SHA file with another filename.

The operation owns one frozen binding per selected root and manifest seal, shared by readers, validators, prewrite guards, backup, staged refresh and publication. Actual-only validation and subsequent candidate validation preserve the same actual locations. Lookups recheck their frozen file; explicit prewrite artifact validation rechecks the complete required set. A changed SHA or missing frozen location cannot trigger discovery of another file.

Actual-Excel recovery snapshots retain original manifest bytes/seal and ordered entries with `path`, `sha256`, `bytes`; new snapshots additionally name this `location_contract`. Each entry must match the sealed PDF/role association, the trusted relative descriptor, and its authenticated backup SHA. The known old three-field snapshot is supported only with the same strict role-relative association. Unknown contracts fail closed. After current workbook bytes have changed, recovery validates all backup entries before writing and restores only recorded selected-root paths, then installs those authenticated frozen bindings. It never discovers recovery locations from current SHA, reseals source data, or returns to an available historical origin.

Existing refresh publication journals already record relative paths and exact backup/new SHAs. Their old manifest allowlist uses the same finite descriptor adapter; owner/token/plan/current-byte checks and backup validation remain intact. Refresh may publish a newly sealed local output through its existing transaction; original source manifests, Excel decisions, identities and original computers' files are not rewritten.

Workbook content/source metadata remains checked by its existing consumers. Location admission uses the sealed role/PDF/workbook-SHA association and does not claim to decode an otherwise unknown workbook format. No PDF locator, pronunciation semantics epoch, identity schema, actual/expected evidence, generic anchor, renderer or transaction-owner contract is changed.
